

El protocolo **Network File System (NFS)**, desarrollado por **Sun Microsystems**, permite acceder a sistemas de archivos a través de una red como si fueran locales. Aunque tiene un propósito similar a **SMB**, utiliza un protocolo completamente diferente.

- **NFS** es utilizado principalmente entre sistemas **Linux** y **Unix**.
- Los clientes **NFS** no pueden comunicarse directamente con servidores **SMB**.
- La autenticación en **NFSv3** se realiza a nivel de equipo, mientras que en **NFSv4**, al igual que en **SMB**, la autenticación es a nivel de usuario.

---

## **Versiones de NFS**

|**Versión**|**Características**|
|---|---|
|**NFSv2**|Operaba sobre **UDP** y tenía soporte limitado.|
|**NFSv3**|Soporta tamaños de archivos variables, mejor reporte de errores, pero no es compatible con clientes **NFSv2**.|
|**NFSv4**|Incluye soporte para **Kerberos**, opera a través de **firewalls**, permite **ACLs** y mejora el rendimiento. Es la primera versión **stateful**.|
|**NFSv4.1**|Soporta **acceso paralelo escalable** (pNFS) y **multipathing de sesiones**. Opera únicamente en el puerto **2049**.|

### **Puertos Comunes:**

- **TCP/UDP 111:** Usado por **RPCbind**.
- **TCP/UDP 2049:** Usado por el servicio **NFS**.

---

## **Configuración Predeterminada**

El archivo de configuración principal de **NFS** es `/etc/exports`. Aquí se especifican los sistemas de archivos que pueden ser exportados y las opciones para cada cliente o red.

### **Archivo de Exports**

```bash
ougicami@htb[/htb]$ cat /etc/exports 

# /etc/exports: la lista de control de acceso para sistemas de archivos exportados
#
# Ejemplo para NFSv2 y NFSv3:
# /srv/homes       hostname1(rw,sync,no_subtree_check) hostname2(ro,sync,no_subtree_check)
#
# Ejemplo para NFSv4:
# /srv/nfs4        gss/krb5i(rw,sync,fsid=0,crossmnt,no_subtree_check)
# /srv/nfs4/homes  gss/krb5i(rw,sync,no_subtree_check)
```

---

## **Opciones Comunes en /etc/exports**

| **Opción**           | **Descripción**                                   |
| -------------------- | ------------------------------------------------- |
| **rw**               | Permisos de **lectura y escritura**.              |
| **ro**               | Permisos de **solo lectura**.                     |
| **sync**             | Transferencia **sincrónica** de datos.            |
| **async**            | Transferencia **asincrónica** de datos.           |
| **secure**           | No se usarán puertos mayores a **1024**.          |
| **insecure**         | Se permiten puertos mayores a **1024**.           |
| **no_subtree_check** | Desactiva la verificación de subdirectorios.      |
| **root_squash**      | El usuario **root** será tratado como **nobody**. |

---

### **Creación de un Recurso Compartido NFS**

```bash
root@nfs:~# echo '/mnt/nfs  10.129.14.0/24(sync,no_subtree_check)' >> /etc/exports
root@nfs:~# systemctl restart nfs-kernel-server 
root@nfs:~# exportfs

/mnt/nfs      	10.129.14.0/24
```

**Explicación:**

- El directorio `/mnt/nfs` se ha compartido con la subred **10.129.14.0/24**.
- Permite **lectura y escritura** con verificación de subárbol desactivada.

---

## **Configuraciones Peligrosas**

|**Opción**|**Descripción**|
|---|---|
|**rw**|Permite **lectura y escritura**.|
|**insecure**|Permite puertos mayores a **1024**.|
|**no_root_squash**|Permite que **root** mantenga sus permisos.|
|**nohide**|Monta sistemas de archivos anidados.|

**Riesgo:**

- El uso de **no_root_squash** puede permitir que un atacante con acceso **root** tenga control completo sobre el sistema.

## **Footprinting del Servicio NFS**

### **Escaneo Básico con Nmap**

```bash
ougicami@htb[/htb]$ sudo nmap 10.129.14.128 -p111,2049 -sV -sC
```

**Salida:**

```
PORT    STATE SERVICE VERSION
111/tcp open  rpcbind 2-4 (RPC #100000)
2049/tcp open  nfs_acl 3 (RPC #100227)
MAC Address: 00:00:00:00:00:00 (VMware)
```

**Explicación:**

- El puerto **111** corresponde a **RPCbind**.
- El puerto **2049** está asociado a **NFS**.

---

### **Escaneo con Scripts NSE de Nmap**

```bash
ougicami@htb[/htb]$ sudo nmap --script nfs* 10.129.14.128 -sV -p111,2049
```

**Salida:**

```
PORT     STATE SERVICE VERSION
111/tcp  open  rpcbind 2-4 (RPC #100000)
| nfs-ls: Volumen /mnt/nfs
| rw-r--r--   0      0      1872  id_rsa
| rw-r--r--   0      0      348   id_rsa.pub
| rw-r--r--   0      0      0     nfs.share
```

**Explicación:**

- Se puede listar el contenido de `/mnt/nfs`.
- Archivos identificados: `id_rsa`, `id_rsa.pub`, `nfs.share`.

## **Montar un Recurso NFS**

### **Listar Recursos Disponibles**

```bash
ougicami@htb[/htb]$ showmount -e 10.129.14.128
```

**Salida:**

```
Export list for 10.129.14.128:
/mnt/nfs 10.129.14.0/24
```

### **Montar el Recurso NFS Localmente**

```bash
ougicami@htb[/htb]$ mkdir target-NFS
ougicami@htb[/htb]$ sudo mount -t nfs 10.129.14.128:/mnt/nfs ./target-NFS/ -o nolock
ougicami@htb[/htb]$ cd target-NFS
ougicami@htb[/htb]$ tree .
```

**Salida:**

```
.
└── mnt
    └── nfs
        ├── id_rsa
        ├── id_rsa.pub
        └── nfs.share
```

---

### **Listar Contenido con Nombres de Usuario y Grupos**

```bash
ougicami@htb[/htb]$ ls -l mnt/nfs/
```

**Salida:**

```
-rw-r--r-- 1 root root 1872 id_rsa
-rw-r--r-- 1 root root  348 id_rsa.pub
-rw-r--r-- 1 root root    0 nfs.share
```

### **Listar Contenido con UIDs y GIDs**

```bash
ougicami@htb[/htb]$ ls -n mnt/nfs/
```

**Salida:**

```
-rw-r--r-- 1 0 0 1872 id_rsa
-rw-r--r-- 1 0 0  348 id_rsa.pub
-rw-r--r-- 1 0 0    0 nfs.share
```

---

### **Desmontar Recurso NFS**

```bash
ougicami@htb[/htb]$ sudo umount ./target-NFS
```

---

## **Resumen Clave:**

- **NFS** permite compartir archivos en redes Linux/Unix.
- **Peligros:** `no_root_squash`, `rw`, `insecure`.
- Herramientas útiles: **Nmap**, **showmount**, **mount**.
- Montar recursos localmente facilita la enumeración y manipulación de archivos.

NFS mal configurado puede exponer archivos sensibles, permitiendo acceso no autorizado y escalada de privilegios.
